# Phase 5: Team (users) local-first Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline, native). Steps use checkbox syntax. **No git commands** (user commits; only `git add` if asked). Run tests in the FOREGROUND only. DB stays v14.

**Goal:** Owner manages team members (add, edit, role, shop, deactivate/reactivate) with no server; a stale role/shop change is never applied silently.

**Architecture:** Same shape as Phase 3/4 customers. `UserService` is the only local writer (row in `synced_entities` entity `user` + outbox row in one `LocalWriter.write`). `UserApplier` (already pulls `user` rows) gains `onPushResult` (adopt version, re-base queued rows, revert on rejection). `UserConflictService` resolves parked rows ("Apply mine again" / "Dismiss"). `UsersRepoImpl` swaps REST for local reads. Marks (pending/failed) are derived from the outbox via `CatalogSyncMarks`.

**Tech Stack:** Flutter, sqflite, bloc, fpdart, FakeSyncServer test harness.

**Spec:** docs/superpowers/specs/2026-11-17-phase5-team-design.md. Parent: 2026-11-16-offline-first-sync-design.md; BE_GAPS section 9; BE `apps/sync/handlers.py` (`user_create`, `user_update`, `_check_stale`).

## Global Constraints
- Owner-only mutations; BE refuses edits of the owner row and of the caller's own row (`forbidden`).
- Feed/`server_state` user shape: `{id, version, phone, full_name, role, default_shop, is_active, status: "active"|"invited", last_login_at, created_at}` (note `default_shop`, `status`; NOT `default_shop_id`/`is_verified`).
- Push payloads: create `{id, phone, full_name, role, default_shop_id?}`; update `{full_name?, role?, default_shop_id?, is_active?}` (only changed fields); `set_role` `{role}`; `set_shop` `{default_shop_id}`; `deactivate` `{}`. `set_role`/`set_shop` REQUIRE `base_version` (else `validation_error`).
- Stale `base_version` on role/shop (also on `update` that carries role/default_shop_id) -> `conflict_version` + `server_state`. Never retried automatically.
- Cashier scope: local store holds only the cashier's own `user` row; Team screens remain owner-only.
- Reuse `catalogResult`/`CatalogValidationException`, `CatalogSyncMarks`, `CatalogSupport`, `OutboxStore.discard/retryRejected`; do not add a parallel mechanism.

## Review Focus
1. Two edits queued while offline: the 2nd must not self-conflict with the 1st (re-base on own success only).
2. Edit queued behind an unsent create (row version null): never sent as `set_role` with null base.
3. Another device changed the user between (version > base+1): the queued role change must conflict, not be re-based.
4. Dismiss of a rejected edit when other edits are still queued: local row = server base + remaining queued payloads.
5. Dismiss of a rejected/never-sent create removes the local row (no ghost member); phone clash (`conflict_unique`) shows reason.
6. Own account / owner row offered no edit actions; cashier device sees only itself.
7. `account_disabled`/`device_revoked` with unsynced team rows: outbox rows survive.

### Task 5: UserConflictService (Apply mine again / Dismiss)
**Files:** Create `lib/features/users/domain/user_conflict_service.dart`; Test `test/features/users/user_conflict_service_test.dart`.
**Interfaces:** `UserConflictService({required LocalWriter writer, required OutboxStore outbox})`:
- `Future<void> applyMineAgain(String mutationId)`: one `LocalWriter.write`: load the rejected row (must be `conflict_version`, entity `user`), read the user row's current version, re-enqueue the same op+payload with `baseVersion = currentVersion`, then delete the old rejected row, and re-apply the payload to the local row json (so UI shows the intended value as pending again). Throws if not rejected/not found.
- `Future<void> dismiss(String mutationId)`: one write: `OutboxStore.discard`-equivalent in the txn for the row; if it was a `create` -> `CatalogSupport.dropNeverSentCreate` then delete the local row (and its remaining open rows); else rebuild row json = `_server` overlaid with payloads of the remaining open outbox rows for that user in `seq` order; remove `_server` if none remain.

- [ ] Failing tests: `applyMineAgain re-queues with fresh base and applies when server unchanged`; `applyMineAgain conflicts again if server changed again` (still never silent); `dismiss restores server role`; `dismiss with another queued edit keeps that edit`; `dismiss of rejected create removes the row`; `applyMineAgain on non-conflict row throws`.
