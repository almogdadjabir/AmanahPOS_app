My calls (change any)

  • Cashier discount setting: cashier_discount_mode = off / approval / free, default off, set by the owner on the dashboard with the other till switches (new backend ask, G8). The phone only reads it; I cannot write business switches from the phone today. Until the backend sends it, cashiers have no discount (same as now).
  • Who is asked for the PIN: only cashiers. Owner and manager pass straight through (desktop only lets the owner through; say if managers should be asked too).
  • What needs the owner PIN for a cashier: a discount (when mode is "Owner PIN"), a return/refund, cancelling a sale, removing or adjusting stock, applying a stock count. Adding stock and selling need none. Mode "Free" skips the PIN for discounts only.
  • How the PIN is checked: against the owner PINs saved on this phone (works offline). If none is saved, the message in screen 5. Five wrong tries lock approval for 30 seconds; the counter lives in memory, so restarting the app clears it.
  • One approval = one action. No "approved for 5 minutes".
  • Cancel sale: from sale detail, written locally and queued as sale.cancel. Stock goes back when the phone syncs (the server returns the new stock), like returns today. A sale with any refund cannot be cancelled. Sales not yet synced can be cancelled too.
  • Shifts: a cancelled cash sale is taken out of the expected cash.
  • Not in this phase: approval for debt write-offs, a per-cashier discount limit, un-cancelling.
