Phase 5: On account and customer debts

Sell on account to a customer, see what each customer owes, receive payments, write off. Same design system as phases 3 and 4.

My proposals (tell me what to change):
1. Customer on the sale: new optional customer row at checkout. It is required only for On account (also as a part of a Split).
2. Balance = sales on account + refunds-adjusted entries − payments − write-offs, computed from this phone's ledger. Until the backend feeds debts to phones (G5/G6), a customer's debts taken on another till are not visible here, and the screen says "from this phone's records".
3. Receive payment: cash or Bankak, amount from 0.01 up to the balance. A cash payment goes into the open shift's drawer (it fills the "debt payments" line that is 0 today). Offline-first: queued as debt.payment.
4. Write off: owner and manager only, queued as debt.writeoff; the server also enforces the role. It never touches the drawer.
5. Refund rule (desktop #65/#66): mobile cannot create refunds today, so nothing to block now. If refunds come to mobile, a sale with an on-account part will be refused for refund, same as desktop.
6. Switch off (on_account_enabled): no Account option, no On account row in Split, no Debts row, no balance on customers. Old ledger data stays stored. A server that is older still accepts sales.
7. A customer with a balance cannot be deactivated silently: the existing deactivate sheet will warn "still owes X".
