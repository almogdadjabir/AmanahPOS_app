Phase 4: Split payments

One sale paid by more than one method. Cash and Bankak now. On account joins in Phase 5 as a third row. Uses the app design system (sheet, segmented, form rows, amounts).

My proposals (tell me if you want any changed):
1. Switch off: the Split option is hidden and the till behaves exactly as today.
2. Charge is on only when parts add up to the total to the cent. One filled row equal to the total is allowed and is saved as a normal single-method sale (same as desktop).
3. A part of 0 or an empty row is dropped. No change-due maths for split.
4. Bankak row follows today's rule: needs the Bankak account in Settings.
5. Parts are written to sale_payments and the sale method is "split"; the server already accepts this. An old server ignores the switch, so a split sale is never lost.
6. Refund rule (desktop #65/#66, on-account part cannot be refunded) comes with Phase 5, where the on-account part exists.
